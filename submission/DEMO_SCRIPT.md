# Three-minute submission demonstration

This is the capture script for the current package. It demonstrates the
human-in-the-loop experience without exposing code or making an additional
cloud call. The visible page is the compiled Blazor WebAssembly app using
redacted recorded receipts from the completed analyst and judge integrations.

## 0:00–0:25 — establish the problem

Open the local app and say:

> “Carrot Tuning separates two responsibilities. The local evaluator owns
> repeatable game evidence. Foundry roles explain that evidence and frame the
> next question. Neither model gets to edit policy or approve an experiment.”

Point to the packet card: four declared values, two seats, one fixed smoke seed,
and the green deterministic-gate status.

## 0:25–1:20 — ask the Evidence Analyst

1. Leave **Evidence Analyst** selected.
2. Check the human-review acknowledgement.
3. Ask: `What does this packet actually establish?`
4. Read the response and point out that it repeats packet-backed aggregates,
   preserves the smoke-fixture limitation, and does not rank candidates.

Say:

> “This is the safe boundary: explanation is useful, but the response remains
> pending human review and carries no source-policy authority.”

## 1:20–2:15 — inspect the judge and Proposal Drafter

1. Select **Evidence Analyst Judge** and point out the independent 1.0 quality score.
2. Select **Proposal Drafter**.
3. Ask: `What should we measure next?`
4. Read the response and point out the single held-out seed/seat measurement.

Say:

> “The second role can turn evidence into one bounded follow-up question. It
> cannot turn that question into approval, candidate expansion, or a source
> edit.”

## 2:15–3:00 — close on governance

Return to **Evidence Analyst** and say:

> “The notebook history proves how the components were built. The package is
> the economical runtime: promoted source, tests and gates, a reproducible
> build command, and this review surface. The next packaging slice replaces
> the receipt-backed UI preserves the same review boundary as the live Foundry
> roles; no credential or policy authority crosses into the browser.”

Do not open a terminal, notebook, Azure portal, or source file during the
recording. The point of this screen is to show the decision boundary clearly.
